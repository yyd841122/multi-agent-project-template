# Tasks Example

> **说明**：这是一个任务清单示例，展示 Planner Agent 应该如何拆分任务。
> 本示例包含 4 个示例任务，不包含完整的项目历史任务。
> 请根据实际项目需求拆分任务。

---

## 任务状态说明

- **pending** - 待分配
- **in_progress** - 开发中
- **completed** - 已完成

## 任务优先级说明

- **P0 (最高优先级)** - 核心基础功能，阻塞其他任务
- **P1 (高优先级)** - 主要功能，应该优先完成
- **P2 (中优先级)** - 重要功能，可并行开发
- **P3 (低优先级)** - 优化和完善，可最后完成

---

## 任务拆分原则

### 1. 任务粒度

**每个任务应该**：
- 在 30 分钟内完成
- 可以独立完成
- 可以独立验收
- 有明确的输入和输出

**每个任务必须包含**：
- 任务 ID（例如：T001、T002）
- 任务名称
- 任务描述
- 验收要点
- 依赖关系
- 优先级

### 2. 任务 ID 命名规则

- 格式：`T` + 3 位数字（例如：T001、T002）
- 从 T001 开始编号
- 按照执行顺序递增

### 3. 验收标准要求

- ✅ 明确具体：不使用"美观"、"友好"等模糊词
- ✅ 可验证：可以通过测试检查
- ✅ 完整：覆盖任务的所有要求
- ✅ 可测试：Tester 可以据此进行验收

**示例**：

✅ **正确**：
- "页面包含输入框，输入框有 id='taskInput'"

❌ **错误**：
- "页面设计美观"

### 4. 重构类任务的特殊要求

如果任务是重构类任务（代码重构、样式重构），必须在任务描述和验收标准中明确写出：

1. **重构不得改变历史功能行为**
2. **要求 Tester 执行历史功能回归检查**

**示例**：

```markdown
### T005: 代码重构与优化

**任务描述**:
对现有代码进行重构，提升代码质量和可维护性。
**重要**：重构不得改变历史功能行为，只改代码结构，不改功能行为。

**验收要点**:
1. JavaScript 代码使用函数封装，避免全局变量污染
2. 函数命名清晰，职责单一
3. **重构任务要求**：
   - 所有历史功能（T001-T004）必须保持正常工作
   - 用户输入行为不能改变
   - 不得擅自使用会改变用户输入的方法
4. **回归测试要求**：
   - Tester 必须测试所有已实现的功能
   - 确认行为一致性
```
