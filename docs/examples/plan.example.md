# Plan Example

> **说明**：这是一个实施计划示例，展示 Planner Agent 应该如何输出项目实施计划。
> 本示例来自 todo-agent-workflow-demo 项目的简化版本。
> 请根据实际项目需求修改此模板。

---

## 1. 实施目标

### 1.1 核心目标（流程验证）

- ✅ 验证多 Agent 协作的可行性
- ✅ 建立清晰的 Agent 角色分工
- ✅ 测试任务拆分与调度机制
- ✅ 实现独立开发与独立验收流程
- ✅ 验证测试失败后的修复流程
- ✅ 沉淀可复用的协作经验

### 1.2 次要目标（功能实现）

- 完成一个功能完整的[业务项目]（作为验证载体）
- 积累多 Agent 协作的最佳实践
- 形成可复制的多 Agent 协作模板

---

## 2. 技术约束

### 2.1 技术栈

说明项目使用的技术。

**示例**：
- **前端技术**：HTML5、CSS3、JavaScript（Vanilla）
- **设计原则**：
  - 保持简单，避免复杂框架
  - 使用原生 API，降低学习成本
  - 代码清晰，便于多 Agent 理解
  - 模块化设计，便于任务拆分

### 2.2 设计约束

**示例**：
- 不使用 React、Vue、后端服务或数据库
- 每个任务应在 30 分钟内完成
- 代码可读性优先于性能优化

## 3. 阶段划分

将项目划分为多个阶段，每个阶段有明确目标。

### 3.1 阶段 0：准备阶段

**目标**：建立项目基础

- [ ] 创建项目目录结构
- [ ] 编写需求文档（`docs/requirements.md`）
- [ ] 创建空白计划文件

### 3.2 阶段 1：基础结构搭建

**目标**：建立可运行的基础骨架

**示例任务**：
- 创建基础文件（HTML、CSS、JS）
- 实现页面基础布局
- 实现基础样式

**验收标准**：
- 项目可以在浏览器中打开
- 显示基本页面结构

### 3.3 阶段 2：核心功能实现

**目标**：实现主要功能

**示例任务**：
- 实现添加功能
- 实现删除功能
- 添加输入校验

**验收标准**：
- 核心功能正常工作
- 基本用户体验流畅

### 3.4 阶段 3：优化与完善

**目标**：提升用户体验和代码质量

**示例任务**：
- 添加空状态提示
- 优化样式细节
- 添加键盘支持

**验收标准**：
- 界面美观整洁
- 用户体验友好

### 3.5 阶段 4：最终验收

**目标**：全功能测试与文档完善

- [ ] 执行完整功能测试
- [ ] 更新使用文档
- [ ] 总结协作流程

## 4. 任务依赖

说明任务之间的依赖关系。

### 4.1 依赖类型

- **文件依赖**：任务 B 需要任务 A 创建的文件
- **功能依赖**：任务 B 需要任务 A 实现的功能
- **数据依赖**：任务 B 需要任务 A 准备的数据

### 4.2 依赖示例

```
T001（创建文件）
  │
  ▼
T002（页面结构） ─────────────┐
  │                          │
  ▼                          │
T003（基础样式）              │
  │                          │
  ├──────────────────────────┘
  │
  ▼
T004（核心功能）
  │
  ├──► T005（功能增强）
  └──► T006（其他功能）
```

## 5. 风险点

识别项目风险并制定应对措施。

### 5.1 流程风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 任务粒度不合理 | 开发困难或频繁切换 | 计划 Agent 仔细评估，任务应可在 30 分钟内完成 |
| 验收标准模糊 | 测试争议 | 每个任务必须有明确的、可验证的验收标准 |
| Agent 上下文丢失 | 信息遗漏 | 使用标准化报告格式，关键信息书面化 |

### 5.2 开发风险

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 一次改太多 | 超出任务范围 | 强调最小必要修改原则 |
| 重构破坏历史功能 | 行为改变 | 重构任务必须做回归测试 |
| 修复循环过多 | 影响进度 | 开发 Agent 仔细自测，最多 3 轮修正 |

## 6. 验收策略

### 6.1 任务级验收

每个任务完成后：
1. Developer Agent 提交开发报告
2. Tester Agent 独立验收
3. 根据验收结果判定 PASS 或 FAIL

### 6.2 阶段级验收

每个阶段完成后：
1. 检查阶段目标是否达成
2. 执行回归测试（如适用）
3. 更新项目文档

### 6.3 项目级验收

项目完成后：
1. 执行完整功能测试
2. 检查代码质量
3. 验证文档完整性
4. 生成项目总结报告

## 7. 多智能体协作架构

### 7.1 Agent 角色定义

#### 主 Agent (Coordinator)
- **职责**：任务调度、流程控制、决策协调
- **输出**：任务分配指令、验收决策

#### 计划 Agent (Planner)
- **职责**：任务拆分、依赖分析、验收标准制定
- **输出**：任务清单、依赖图、验收标准

#### 开发 Agent (Developer)
- **职责**：独立完成分配的开发任务
- **输出**：可运行的代码、开发报告

#### 测试 Agent (Tester)
- **职责**：独立验收开发成果
- **输出**：测试报告、Bug 报告或验收通过确认

### 7.2 协作流程

```
需求文档
   │
   ▼
计划 Agent ──► 任务清单
   │
   ▼
主 Agent 选择任务 ──► 开发 Agent ──► 测试 Agent
   │                                    │
   └────────────────────────────────────┘
              测试通过？
                 │
        ┌────────┴────────┐
       是                 否
        │                 │
        ▼                 ▼
    下一个任务        修正循环（最多 3 轮）
```

## 8. 成功标准

### 8.1 项目成功标准

- ✅ 所有核心功能测试通过
- ✅ 至少完成 3 个完整的开发-验收循环
- ✅ 至少经历 1 次测试失败-修复-再通过的流程（可选）
- ✅ 代码质量良好，无明显 Bug
- ✅ 协作流程文档完整

### 8.2 流程验证标准

- ✅ 任务拆分合理，粒度适中
- ✅ Agent 角色分工清晰
- ✅ 测试验收独立有效
- ✅ 修复流程闭环成功（如有修正循环）
- ✅ 主 Agent 调度顺畅

## 9. 时间估算

**示例**（仅作参考）：

- 阶段 0（准备）：已完成
- 阶段 1（基础）：30-45 分钟
- 阶段 2（核心）：60-90 分钟
- 阶段 3（优化）：30-45 分钟
- 阶段 4（验收）：30 分钟

**总计**：约 3-5 小时（包含多轮测试和修复）

**注意**：实际时间因项目复杂度而异，仅供参考。
